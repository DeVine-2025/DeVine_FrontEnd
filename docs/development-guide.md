# 최소 탐색과 검증 규칙
실제 소스 확인일: 2026-11-12.

## 작업 순서
1. 사용자 요청으로 대상 화면·기능을 정한다. `architecture.md`의 해당 행과 진입 파일부터 읽는다.
2. 해당 파일의 직접 import, 관련 훅·API·스타일만 따라간다. 공통 코드 변경 시 사용처를 rg로 추가 확인한다.
3. 기존 분석·구조 보고서를 매번 전부 읽거나 전체 프로젝트를 다시 나열하지 않는다. 삭제·전역 변경·사용처 불명확 시에는 조사 범위를 확장한다.
4. 문서는 위치 안내다. 실제 코드·라우트·참조를 확인한 뒤 수정한다. 문서와 소스가 다르면 소스를 기준으로 문서도 고친다.
5. 현재 작업과 관계없는 변경사항을 되돌리지 않는다. 커밋·푸시는 그 작업에서 명시적으로 요청받았을 때만 한다.

## 파일 구조
- 새 파일은 케밥 케이스를 기본으로 한다. 기존 파일을 작업과 관계없이 일괄 개명하지 않는다.
- 한 화면에서만 쓰는 훅·검증·변환은 해당 pages 폴더에 둔다.
- 실제 여러 화면에서 사용하는 컴포넌트만 shared로 옮긴다. 향후 재사용 가능성만으로 추상화하지 않는다.
- 코드 줄 수만으로 분리하지 않고 UI·데이터 처리·독립 상태 등 책임 경계를 기준으로 분리한다.
- API·목데이터 필드와 데이터 모드 분기는 리팩터링 과정에서 삭제하지 않는다.
- 미사용 판단은 import/export, 라우트, HTML 진입점, 테스트, 동적 참조, API 모드를 함께 확인한다.

## 검증 명령
명령은 프로젝트 루트에서 실행한다. 새 패키지 설치 없이 기존 Yarn을 사용한다.

```powershell
yarn tsc -p tsconfig.app.json --noEmit --pretty false
yarn tsc -p tsconfig.node.json --noEmit --pretty false
yarn build
git diff --check
```

인증 관련 변경 시:
```powershell
yarn vitest run --config vitest.auth.config.ts
```

- 현재 yarn build는 루트 tsconfig.json의 tsc -b를 실행한다. app/node 엄격 설정 검사 대용으로 취급하지 않는다.
- 전체 포맷·lint 자동 수정을 실행하지 않는다. 필요하면 수정 파일만 대상으로 한다.
- 문서만 수정한 경우 링크·경로·git diff --check로 검증하고 앱 빌드를 반복하지 않는다.
- 브라우저 확인 시 실제 확인한 화면·뷰포트·흐름을 기록한다. 인증·서버 접근 부족으로 미검증인 기능을 통과로 보고하지 않는다.
- 결제·메시지 전송 등 외부 상태 변경을 단순 UI 검증 목적으로 실행하지 않는다.
- 캡처·로그·임시 진단 파일은 저장소 밖에 둔다.

## 문서 유지
라우트·담당 파일·공통 컴포넌트·검증 명령이 변경되면 관련 안내도 같은 작업에서 갱신한다.
최근 작업 일지나 코드 전문을 AGENTS.md에 누적하지 않는다. AGENTS에는 필수 규칙과 필요한 문서 링크만 유지한다.
